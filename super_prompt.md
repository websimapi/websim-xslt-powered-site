# Super Prompt: Refactor XSLT Monolith into Modular Templates

## 1. Project Context

You are working on a static website that is built using a unique, JavaScript-free architecture. The entire site is rendered client-side by the browser's native XSLT processor.

The core components are:
-   **XML files**: These contain the raw, structured content for each page (e.g., `index.xml`, `posts/deep-dive-xslt.xml`).
-   **`template.xsl`**: A single, monolithic XSLT file. It acts as the "template engine" that transforms all XML content files into final HTML pages.
-   **`style.css`**: A standard CSS file for styling the generated HTML.

When a user navigates to an `.xml` file, the `<?xml-stylesheet ...?>` processing instruction tells the browser to apply `template.xsl` to it, generating the HTML to be rendered.

## 2. The Problem: A Monolithic XSLT File

The current implementation has all XSLT logic consolidated into a single, large `template.xsl` file. This file is becoming difficult to maintain and understand. It contains:
-   The main HTML page layout (head, body, header, footer).
-   Templates for different page types (`post`, `post-index`, `about`).
-   Templates for rendering specific complex components (`dataTable`, `taxonomy`, `principlesList`, etc.).

This monolithic approach violates the principle of separation of concerns and makes the template logic hard to navigate and reuse.

## 3. The Goal: Modularize `template.xsl`

Your task is to refactor `template.xsl` by splitting it into a collection of smaller, more focused XSLT files. The goal is to improve maintainability, readability, and reusability of the XSLT code.

**Crucially, this is a pure refactoring task. The final HTML output generated by the browser for any given XML page must remain identical to the current implementation.**

## 4. Proposed File Structure
